# 8-Channel Delay-and-Sum — Fixed Point versus Floating Point on Artix-7

The same beamformer datapath built twice, once in fixed point and once in IEEE-754
single precision, synthesised for three Digilent boards so the cost of the two
number formats can be **measured** rather than argued about.

## What the two designs are

Identical structure, so the comparison is fair:

```
per channel:  delay-line read  ->  linear interpolation  ->  apodisation multiply
then:         balanced adder tree across the 8 channels
```

| | `das8_fixed` | `das8_float` |
|---|---|---|
| Sample | 12-bit signed | IEEE-754 single |
| Weight | 8-bit signed | IEEE-754 single |
| Product | 21-bit signed | single |
| Accumulator | 32-bit signed | single |
| Arithmetic | fabric and DSP48 | Floating-Point Operator IP |
| Cores instantiated | 8 multipliers, 7 adders | **8 sub + 16 mul + 15 add = 39 IP cores** |
| Latency | 7 clocks | 23 clocks |
| Throughput | 1 point per clock | 1 point per clock |

The 39-against-15 instance count is most of the answer before you synthesise anything.

---

## The arithmetic contract

`rtl/das8_fixed.v` must reproduce this exactly or the testbench will not pass:

```
diff = s1 - s0                   signed, IN_W+1
m    = diff * frac               signed, frac unsigned FRAC_W
samp = s0 + (m >>> FRAC_W)       arithmetic shift, truncates toward -inf
prod = samp * w                  signed
acc  = balanced adder tree over the 8 products
```

`>>> FRAC_W` **truncates**; it does not round. Change it here and you must change
`ref/das8_model.py` identically, or every comparison shows an error you will spend
an hour chasing.

## Step by step

### 0. Prerequisites

Vivado 2020.2 or later and Python 3 with numpy. No board is needed for the
comparison table — only for the ILA flow.

### 1. Generate the stimulus and golden results

```bash
python3 ref/das8_model.py
```

Expected:

```
fixed-point NRMSE vs double : -63.4 dB
accumulator: bound 23 bits, actually used 21 bits
wrote stimulus and golden files to sim/  (8 ch, 2048 deep, 64 points)
```

If the NRMSE differs, stop. Everything downstream is referenced to it.

### 2. Simulate before you synthesise

```bash
vivado -mode batch -source tcl/sim.tcl -tclargs fixed
vivado -mode batch -source tcl/sim.tcl -tclargs float
```

Expect `PASS: all 64 points bit-exact` for fixed and `PASS: all 64 points within
tolerance` for float. Floating point is checked to a relative tolerance of 1e-5,
not bit-exactly, because the IP rounds at every stage and the double-precision
reference does not round the same way.

### 3. Synthesise for the three boards

```bash
./run_all.sh
```

or one at a time:

```bash
vivado -mode batch -source tcl/run_board.tcl -tclargs basys3
vivado -mode batch -source tcl/run_board.tcl -tclargs arty_a7_100
vivado -mode batch -source tcl/run_board.tcl -tclargs nexys_a7_100
```

This writes `reports/utilisation.csv`:

```
board,part,variant,ila,LUT,FF,DSP,BRAM36,WNS_ns
```

Those are the numbers for the presentation table.

### 4. Add the ILA and go to hardware

```bash
./run_all.sh ila
```

or:

```bash
vivado -mode batch -source tcl/run_board.tcl -tclargs nexys_a7_100 ila
```

This implements the design, inserts an ILA on `result`, `out_valid` and `point`,
and writes `.bit` and `.ltx` into `reports/<board>/`.

To capture: open the Hardware Manager, program the `.bit`, load the `.ltx`, trigger
on `out_valid == 1`, capture 1024 samples, export the `result` column and compare
against `sim/golden_fixed.hex`.

**Run the no-ILA flow first.** The ILA consumes LUTs, FFs and BRAM itself, so a
table built from ILA runs measures the debug core as well as the design.

## What to look for

1. **DSP count.** Fixed point should take about 8 — one per channel. Each
   floating-point multiplier takes several, so expect a large multiple. On the
   Basys 3, with 90 DSPs, this is where the float design approaches the limit.
2. **LUT count.** The 15 floating-point adders are mostly fabric: exponent
   alignment, normalisation and rounding.
3. **BRAM.** Fixed stores 12-bit samples, float stores 32-bit — roughly 2.7× the
   memory for identical data.
4. **WNS.** Report the clock each design actually closes at, not merely whether
   100 MHz passed.

Then repeat with `FP_MULT_USAGE` set to `No_Usage` in `tcl/create_fp_ip.tcl`. That
builds the floating-point multipliers entirely from LUTs and shows the DSP-against-
LUT trade directly.

## Common problems

| Symptom | Cause |
|---|---|
| Memories read as all zero | the `.hex` files are not in the synthesis fileset, or the working directory differs |
| Float testbench fails on every point | `FP_LATENCY` in the TCL does not match `FP_LAT_*` in `das8_float.v` |
| Fixed testbench off by a small amount everywhere | rounding used instead of truncation in the interpolation |
| BRAM count is zero | `ram_style` stripped, or depth below the inference threshold |
| Float will not fit on Basys 3 | expected with `FP_MULT_USAGE = No_Usage` — that is a result, report it |
| The two A7-100 boards disagree | same silicon; the difference is in your flow |
